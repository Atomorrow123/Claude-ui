# Claude UI · 界面构建指南

> 好的界面不是"加了多少东西"，而是"每一样东西都有理由在那里"。
> 克制、清晰、有温度 —— 先保证可读与可用，再谈风格。

---

## 0. 核心信条（每次都要记住）

1. **先定方向，再写代码。** 没有设计意图的界面必然平庸。动手前先写 3 行设计简报（见 §1）。
2. **Token 先行。** 颜色、字号、间距、圆角、阴影、动效全部来自一套有限的 token，禁止魔法数字。
3. **一屏一个焦点。** 每个视图只允许一个视觉主角；层级靠 *大小 → 字重 → 颜色* 依次拉开，不要三样同时用满。
4. **留白是设计元素，不是浪费。** 拿不准时，把间距放大一档。
5. **克制用色。** 中性色承担 90% 的界面，强调色只给真正需要被点击/注意的东西。
6. **所有状态都要设计。** hover / focus / active / disabled / loading / empty / error 缺一不可。
7. **尊重现有系统。** 如果项目已有设计系统或组件库，优先遵循它，本指南只用于补全与提升。

---

## 1. 工作流程

```
理解场景 → 设计简报 → 定义 Token → 灰度骨架 → 组件与状态 → 打磨 → 自检（最好截图验证）
```

### Step 1 · 理解场景
动手前回答：
- **谁在用？** 专业用户（高密度、效率优先）还是大众用户（引导、情绪优先）？
- **什么设备？** 桌面为主还是移动优先？
- **内容是什么？** 数据型、阅读型、营销型、工具型？
- **已有约束？** 现有品牌色、组件库（shadcn/ui、Ant Design、MUI…）、框架（Tailwind / CSS Modules / CSS-in-JS）。

### Step 2 · 写设计简报（3 行，写在回复或注释里）
```
气质：  温暖、克制、像一本好的杂志（例）
方向：  Claude 原生 / 编辑排版 / 瑞士极简 / 暗色精密 / 柔和亲和 / 新粗野主义（见 references/aesthetic-directions.md）
签名细节：衬线大标题 + 赤陶色强调 + 细边框代替阴影（例）
```
"签名细节"是让界面被记住的 1–2 个独特选择 —— 只要 1–2 个，多了就乱。

### Step 3 · 定义 Token
从 [references/tokens.css](references/tokens.css) 起步并按方向调整。至少包括：颜色（语义化命名）、字体族、字号阶梯、间距阶梯、圆角、阴影、动效时长与曲线。

### Step 4 · 灰度骨架
先只用中性色把布局、层级、间距搭好。**灰度下层级成立，加颜色才会好看**；灰度下一团糟，颜色救不了。

### Step 5 · 组件与状态
参考 [references/components.md](references/components.md) 的组件配方，每个交互组件补齐全部状态。

### Step 6 · 打磨
对齐、光学修正、微交互、空状态文案、响应式断点、暗色模式。

### Step 7 · 自检
逐条过 §10 清单。如果有浏览器工具可用，**打开页面截图看一眼**，以真实渲染为准，不要凭想象交付。

## 2. 排版 Typography

排版决定了界面 70% 的质感。

### 字号阶梯
使用比例阶梯（推荐 1.2 小三度 用于工具/仪表盘，1.25 大三度 用于通用，1.333 纯四度 用于营销/编辑）：

| Token | 1.25 阶梯 | 用途 |
|---|---|---|
| `--text-xs` | 12px | 标签、辅助说明（慎用，最小不低于 12px） |
| `--text-sm` | 14px | 次要正文、表格、表单标签 |
| `--text-base` | 16px | 正文（移动端正文**不得小于 16px**） |
| `--text-lg` | 20px | 小标题、强调段落 |
| `--text-xl` | 25px | 卡片/区块标题 |
| `--text-2xl` | 31px | 页面标题 |
| `--text-3xl` | 39px | 区块大标题 |
| `--text-4xl` | 49px+ | Hero，用 `clamp()` 做流体字号 |

### 规则
- **行高与字号成反比**：正文 1.5–1.7；标题 1.1–1.25；超大展示字 1.0–1.1。
- **大字收紧字距**：≥ 24px 的西文标题 `letter-spacing: -0.01em ~ -0.03em`；全大写小标签反而放宽 `+0.04em ~ +0.08em`。
- **行宽 60–75 字符**（中文约 35–45 字）：`max-width: 65ch`。
- **字重最多 3 档**：通常 400 / 500 / 600（或 700）。用 300 以下的细字做正文是可读性灾难。
- `text-wrap: balance` 用于标题，`text-wrap: pretty` 用于段落，避免孤字。
- 数字对齐用 `font-variant-numeric: tabular-nums`（表格、价格、计时器必须用）。
- 层级靠 **字号 + 字重 + 颜色深浅** 组合，而不是靠加粗+变色+放大+下划线全上。

### 字体选择
- **不要默认到处 Inter。** 它不是错，但它是"没做选择"的信号。考虑：
  - 无衬线：Geist、IBM Plex Sans、Manrope、DM Sans、Instrument Sans、Figtree、system-ui
  - 衬线（标题/编辑感）：Fraunces、Newsreader、Source Serif 4、Instrument Serif、Lora
  - 等宽：Geist Mono、JetBrains Mono、IBM Plex Mono
- **最多两种字体**：一个标题、一个正文（或同一家族不同字重）。等宽可作为第三种仅用于代码/数据。
- 字体加载：`font-display: swap`，只加载用到的字重，优先可变字体。

### 中文排版（重要）
- 字体栈：`"PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`；编辑感可用 `"Noto Serif SC", "Source Han Serif SC"`；文艺感可用 霞鹜文楷 (LXGW WenKai)。
- 西文字体写在中文字体**前面**，让英文数字走西文字形：`font-family: "Inter", "PingFang SC", ...`
- 中文正文行高 **1.7–1.8**（比西文更松）。
- **不要给中文设置负字距**，不要用斜体（中文没有真斜体，伪斜体很丑）。
- 中英文之间留空格（"使用 React 构建"），或用 `text-autospace` 让浏览器处理。
- 中文标题字重 500–600 往往比 700 更精致。

## 3. 色彩 Color

### 结构
- **中性色阶**（10–12 级）承担背景、表面、边框、文字。
- **1 个品牌/强调色**（主操作、链接、选中态、焦点环）。
- **语义色**：success / warning / danger / info，仅用于状态，不做装饰。
- 比例参考 **60 / 30 / 10**：背景 60%、表面与文字 30%、强调色 ≤ 10%。

### 规则
- **不要纯黑纯白**：文字用 `#1a1915` 一类的近黑，背景用 `#faf9f5` 一类的米白或 `#fafafa`。纯 `#000` on `#fff` 刺眼且廉价。
- **中性色带一点色相**：让灰色向强调色的色相偏 2–8% 饱和度（暖强调配暖灰，冷强调配冷灰），整体会立刻"统一"。
- 推荐用 **OKLCH** 定义色阶，亮度感知均匀：`oklch(62% 0.14 40)`。
- **对比度**：正文 ≥ 4.5:1，大字/图标 ≥ 3:1。次要文字不要灰到看不清（常见错误：`#999` on `#fff` 只有 2.8:1）。
- **文字颜色 3 档就够**：primary（标题/正文）、secondary（说明）、tertiary（占位/禁用）。
- 强调色在大面积背景上要降饱和或用浅色调（tint），实心饱和色只用于小面积按钮/徽标。
- 一页里卡片不要每张换一个颜色 —— 彩虹卡片是新手标志。

### 暗色模式
- **不是简单反色。** 背景用 `#141413`～`#1f1e1d` 一类的深灰（不是纯黑），用**更亮的表面**表示层级上升，而不是阴影。
- 强调色在暗色下**降低饱和、略提亮度**，避免发光刺眼。
- 文字用 `~#ececec` 而不是 `#fff`，次要文字适当提亮保证对比。
- 边框比亮色模式更重要（阴影在暗背景上几乎不可见）。
- 用 `color-scheme: light dark` 与 `light-dark()`/CSS 变量切换，图片与插画考虑降亮度。

## 4. 间距与布局 Spacing & Layout

### 间距阶梯（4px 基准）
`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96 · 128`
只使用阶梯内的值。

### 规则
- **亲密性原则**：组内间距 < 组间间距 < 区块间距。标签与输入框 6–8px，表单项之间 16–24px，区块之间 64–128px。间距相等 = 关系不清。
- **内小外大**：容器内边距 ≤ 容器之间的间距。
- **对齐**：建立清晰的左边线；所有东西都对齐到某条线。居中对齐只用于短内容（Hero 标题、空状态），**长文本和表单永远左对齐**。
- **网格**：桌面 12 栏，内容最大宽度 1120–1280px；阅读型内容 640–720px。
- **不对称有张力**：不要所有区块都"居中标题 + 三列卡片"。尝试左文右图、7/5 分栏、大小交错的 bento 网格。
- **密度匹配用户**：B 端工具可以紧凑（行高 32–40px 的表格行），C 端营销页要松弛。
- 移动端：触控目标 ≥ 44×44px，页面左右边距 16–20px，单列优先。

### 圆角
- 选一套并坚持：如 `4 / 8 / 12 / 16 / 9999`。
- **嵌套圆角公式**：内层圆角 = 外层圆角 − 内边距。（外 16px、padding 8px → 内 8px）
- 圆角大小传递气质：0–4px 精密/专业，8–12px 现代/友好，16–24px 柔和/亲和。全站别混用多种气质。

### 深度：边框 vs 阴影
- **二选一为主**。精致界面常用 *1px 低对比边框 + 极轻阴影*，而非重阴影。
- 阴影要**分层且带色相**，模拟真实光照：
  ```css
  --shadow-md: 0 1px 2px oklch(20% 0.01 60 / 0.06), 0 4px 12px oklch(20% 0.01 60 / 0.08);
  ```
- 阴影只表达"高度"：卡片 < 下拉菜单 < 弹窗。不要给每个元素都加 `shadow-2xl`。

## 5. 组件原则

详见 [references/components.md](references/components.md)。要点：

- **按钮层级**：一个视图里只有一个 Primary；其余用 Secondary / Ghost / Link。危险操作用 danger 色且需要确认。
- **按钮文案用动词 + 宾语**："保存更改"、"创建项目"，不要"提交"、"确定"、"OK"。
- **表单**：标签在上方，永远不要只用 placeholder 当标签；错误信息贴着字段、说清楚怎么改。
- **图标**：用一套图标库（Lucide / Phosphor / Tabler），统一线宽（1.5 或 2）与尺寸（16 / 20 / 24），与文字垂直居中。**不要用 emoji 当 UI 图标。**
- **卡片**：只在内容确实需要分组时使用；不要卡片套卡片套卡片。
- **表格**：数字右对齐 + tabular-nums，文字左对齐；斑马纹或分隔线二选一；表头弱化（小号、次要色、可大写）。

## 6. 动效 Motion

- **动效服务于理解**（空间关系、状态变化、反馈），不是装饰。
- 时长：微交互 100–150ms；常规过渡 200–250ms；大面积/页面级 300–400ms。超过 500ms 会让人觉得慢。
- 曲线：进入用 ease-out（`cubic-bezier(0.2, 0, 0, 1)`），退出用 ease-in 且更快；避免线性和夸张回弹。
- **只动 `transform` 和 `opacity`**，避免动 `width/height/top/left` 引起重排。
- 列表进入可做 20–40ms 的错峰（stagger），总时长控制在 400ms 内。
- 按下态：`scale(0.98)` 足够，不要 0.9。
- **必须支持** `@media (prefers-reduced-motion: reduce)`。
- 不要让每个区块滚动时都淡入上浮 —— 一页里最多一两处有意义的滚动动效。
- 优先使用原生能力：View Transitions、`@starting-style`、scroll-driven animations、`<dialog>` / Popover API。

## 7. 状态与边界情况

每个界面交付前，检查这些状态是否被设计：

| 状态 | 要点 |
|---|---|
| **Loading** | 已知布局用骨架屏（形状与真实内容一致）；短操作用按钮内 spinner 并锁定宽度防抖动；> 300ms 才显示加载态 |
| **Empty** | 说明"这里会有什么" + 一个主操作 + 可选插画；首次空状态是最好的引导时机 |
| **Error** | 说人话：发生了什么 + 怎么办 + 重试按钮；不暴露堆栈 |
| **Partial / 长内容** | 超长文本截断（`text-overflow` / `line-clamp`）+ title 提示；超长列表虚拟化或分页 |
| **Focus** | `:focus-visible` 清晰焦点环（2px 强调色 + 2px offset），**绝不 `outline: none` 了事** |
| **Disabled** | 降低对比 + `cursor: not-allowed`，并尽量告诉用户为什么不可用 |
| **Success** | 轻量 toast 或就地反馈，自动消失，不打断流程 |

## 8. 可访问性（底线，不是加分项）

- 语义化 HTML：`<button>` 用于操作，`<a>` 用于跳转，标题层级 h1→h2→h3 不跳级。
- 所有交互元素可键盘访问，Tab 顺序合理，弹窗打开时焦点陷入、关闭后归还。
- 图标按钮必须有 `aria-label`；装饰图片 `alt=""`。
- 不只靠颜色传达信息（错误状态 = 红色 + 图标 + 文字）。
- 对比度达标（§3）；支持 200% 缩放不破版。

## 9. 反 "AI 味" 清单（务必避开）

以下是 AI 生成界面最常见的平庸信号。详细的"症状 → 替代方案"见 [references/anti-patterns.md](references/anti-patterns.md)。

- ❌ 紫蓝渐变背景 / 渐变文字标题 / 到处发光
- ❌ 所有东西都毛玻璃（glassmorphism）
- ❌ 居中大标题 + "三张一模一样的图标卡片" 的固定套路
- ❌ emoji 当图标（🚀✨💡）
- ❌ `rounded-3xl` + `shadow-2xl` 加在每个元素上
- ❌ 每张卡片一个不同的鲜艳颜色
- ❌ "Unlock the power of…"、"释放无限可能" 这类空洞文案；虚假数据 "10x faster"、"99.9%"
- ❌ 每个区块都滚动淡入上浮
- ❌ 纯黑纯白、灰到看不清的次要文字
- ❌ 只用 placeholder 当表单标签、去掉焦点环
- ❌ 随意的间距值（13px、27px）和三种以上的圆角

## 10. 交付前自检清单

**层级与排版**
- [ ] 眯眼看（或模糊截图）：每屏能一眼找到唯一焦点吗？
- [ ] 字号都来自阶梯？行宽 ≤ 75ch？正文 ≥ 16px（移动端）？
- [ ] 字体 ≤ 2 种，字重 ≤ 3 档？

**色彩**
- [ ] 强调色面积 ≤ 10%？只有一个 Primary 按钮？
- [ ] 文字对比度达标？没有纯黑纯白？
- [ ] 暗色模式（如有）检查过表面层级与强调色饱和度？

**间距与对齐**
- [ ] 所有间距来自阶梯？组内 < 组间 < 区块？
- [ ] 有清晰的对齐线？长文本左对齐？
- [ ] 嵌套圆角符合公式？

**交互与状态**
- [ ] hover / focus-visible / active / disabled 都有？
- [ ] loading / empty / error 都设计了？
- [ ] 动效 ≤ 300ms、只动 transform/opacity、支持 reduced-motion？

**响应式与可访问性**
- [ ] 375px / 768px / 1280px / 1920px 下都检查过？
- [ ] 键盘能走完主流程？图标按钮有 aria-label？
- [ ] 触控目标 ≥ 44px？

**整体**
- [ ] 去掉 AI 味了吗？（§9）
- [ ] 签名细节是否被一致地执行？
- [ ] 文案具体、真实、像人写的？
